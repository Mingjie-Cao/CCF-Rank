# 被引次数模块

本模块仅使用 OpenAlex 自动查询。Google Scholar 通过浏览器人工核对，核对后的次数可手动填写，来源显示为「手动」。

## 使用

1. 在文献列表表头右键，勾选「被引次数」「被引数据源」「被引更新时间」「被引状态」。
2. 选择文献，右键 →「被引次数」→「更新所选条目的被引次数」。支持多选，显示处理进度。
3. 需要持续更新时，在 Zotero 设置 → CCF Rank 中开启「自动查询并更新过期记录」。默认关闭；启用后，读取被引列和新增、修改条目会触发查询，不会启动全库扫描。
4. 状态为「需核对」或自动匹配不足以确认论文时，使用「确认 OpenAlex 论文…」。窗口列出候选标题、作者、年份、出版物、DOI、被引次数和差异说明，可先打开论文页面，再确认对应论文。确认后来源仍为 OpenAlex，后续按该记录自动更新。
5. 确认窗口也无法找到正确论文时，再使用「在 Google Scholar 中核对」和「手动填写被引次数」。手动值在清除记录或文献信息发生变化前保留，强制刷新也不会覆盖；主动确认一条 OpenAlex 论文会恢复自动来源。
6. 「查看查询详情」可检查来源、匹配方式、匹配说明、数据更新时间、最近查询时间和错误。「打开数据源记录」打开对应论文页面。「清除记录并恢复自动查询」也会清除人工确认的论文绑定。

真实的 0 引用显示为 `0`；未查询、未找到、歧义和失败均不伪装成 0。过期或失败时旧值仍显示，状态列明确标记。更新时间指成功获取当前显示数字的时间，不是失败重试时间。

OpenAlex 的引用识别与去重会随数据更新而变化，数字可能下降；本模块允许真实的下降。这里的自动查询结果不等同于 Google Scholar。

## 模块接口

| 模块                     | 职责 / 接口                                                                                                                                        |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `citations/core.ts`      | 纯数据逻辑、`Identity`、`Candidate`、`Result`、`RecordEntry`、DOI 与标题规范化、严格匹配                                                           |
| `CitationService`        | `refresh(identity, force?)`、`get(identity)`、`setManual(identity, count)`、`remove(key)`、`load(raw)`、`serialize()`、`cancelPending()`、`stop()` |
| `Provider`               | `lookup(identity, boundPaperID?): Promise<Lookup>`，返回匹配结果、候选及说明，不修改 Zotero 条目                                                   |
| `citations/providers.ts` | 数据源响应验证、OpenAlex 适配器、限速与退避                                                                                                        |
| `citationCount.ts`       | Zotero 生命周期、条目元数据、列、菜单、批量进度、原子文件持久化                                                                                    |
| `preferenceScript.ts`    | 开关、缓存有效期和可选 API Key 设置                                                                                                                |

`Identity.key` 使用 `libraryID:itemKey`，防止个人库与群组库发生冲突。元数据指纹包含规范化 DOI、标题、年份及第一作者姓氏；元数据改变时旧结果不再适用于该条目。

`RecordEntry` 存储指纹、状态、最近查询时间、可重试时间以及最近成功的 `Result`。`Result` 包含被引次数、来源、论文标识、记录 URL、匹配方式和成功更新时间。失败可以保留最近成功的结果；手动值标记来源为 `manual`。

人工确认使用 `CitationService.findCandidates(identity)` 和 `confirmCandidate(identity, candidate)`：检索共用串行队列，不覆盖已显示的结果；确认后保存 `boundPaperID`，匹配方式为 `confirmed`，来源为 `openalex`。记录中的 `detail` 解释判断依据，`candidates` 在本次运行中供查看；重启后重新检索候选。文献信息变化后，旧绑定不再适用。确认窗口打开后若文献信息改变，旧候选不能继续绑定。

## 匹配与请求

- DOI 去除 `doi:`、解析器 URL 和大小写差异，优先精确查找。
- DOI 未命中或缺失时，使用 OpenAlex 的 `search.title` 先搜索带引号的完整标题短语；没有合理候选才扩大为标题词搜索。不会用全文命中数判断论文是否存在。
- 自动采用要求规范化标题一致，并有年份或作者信息佐证，且只有一个候选满足要求。作者或年份缺失不是信息冲突：例如标题、年份一致，但 OpenAlex 作者列表为空，仍可匹配。双方已有信息明确冲突时不会自动采用。
- 标题相近、年份或作者有差异、仅有标题、多候选以及结果未取全时，保留合理候选供人工确认，并展示具体原因。相近标题只用于人工候选召回，不用于自动认定。
- 人工确认后按 OpenAlex ID 直接读取被引次数，不再每次重复标题匹配；记录暂时不可用时保留旧次数与绑定，并说明需要重新核对。
- OpenAlex 不可用或未获得可信结果时显示失败、未找到或需核对；先尝试确认 OpenAlex 论文，最后才由 Google Scholar 人工核对并填写次数。自动查询不切换到其他数据库。
- 所有请求串行，开始时间间隔至少 1.1 秒，15 秒超时。网络 / 5xx 错误最多重试一次；429 遵循秒数或日期形式的 `Retry-After`，等待超过 30 秒时转入来源冷却，不阻塞整个批次。认证错误会短暂冷却来源。
- 同条目同指纹的并发刷新共用任务；自动队列最多 200 个待处理条目。未排入队列的条目可在后续读取列时再次尝试。手动批量刷新逐个等待。
- 覆盖手动值、删除条目、更改设置和卸载插件会使旧任务结果失效。

## 缓存与隐私

数据保存于 Zotero 数据目录的 `ccf-rank-citations.json`，版本为 2；采用临时文件替换和串行写入。读取旧版本 1 时保留成功结果与手动值，并让旧的未找到 / 歧义记录失效，以免它们阻挡新版匹配。解析损坏数据或未知版本时忽略无效记录，不影响启动。

从混合模式升级时，旧 Semantic Scholar 自动结果和仅涉及该来源的失败记录不再加载；OpenAlex 成功结果及手动记录保留。旧的备用来源开关与密钥首选项不再读取。

成功数据默认有效 7 天，可配置 1–365 天；未找到 / 歧义缓存 1 天；查询错误缓存 15 分钟。手动刷新跳过条目缓存有效期，但仍遵循来源限流。手动值不会自动过期。删除或移入回收站会移除相应记录。此缓存仅保存在本机，不通过 Zotero 同步；不写入 Extra、标签或 DOI 等原有字段。

查询会把 DOI 或标题发往 OpenAlex；作者与年份在本机用于匹配。API Key 可选，存于本机 Zotero 首选项（不是加密密钥库），使用请求头传递；模块的缓存与错误消息不包含密钥。

## OpenAlex 配额

根据 2026-10-11 核查的[官方认证说明](https://help.openalex.org/api/authentication/)和[调用成本说明](https://help.openalex.org/access/example-costs/)：

| 项目                       | 无 API Key         | 免费 API Key    |
| -------------------------- | ------------------ | --------------- |
| 免费每日额度               | $0.10 等值调用额度 | $1 等值调用额度 |
| 仅用于标题搜索时的理论次数 | 约 100 次/天       | 约 1,000 次/天  |
| 按 DOI/ID 直接获取单篇记录 | 不消耗上述额度     | 不消耗上述额度  |
| 常规请求速率上限           | 每秒 100 次        | 每秒 100 次     |

额度按调用成本计量，免费 Key 不要求绑定付款方式；本插件不会购买额度。标题搜索与其他调用共用每日预算，因此实际可用搜索次数可能减少。按 DOI 直接读取免费，并不意味着可以忽略每秒请求上限。免费 Key 增加每日预算，不把每秒速率上限提高 10 倍。

当前插件保持串行和至少 1.1 秒请求间隔，约 0.91 次/秒。429 可能来自请求过快，也可能来自每日额度用尽；每日预算在 UTC 零点（北京时间 08:00）重置。先使用 DOI，再搜索标题，有助于节省额度。

在 [OpenAlex 设置页](https://openalex.org/settings/api)取得 Key 后，填入 Zotero 设置 → CCF Rank → OpenAlex API Key。修改 Key 后再次手动更新条目。

## 验证与验收

运行 `npm run test:citations` 验证匹配、作者信息缺失、短语搜索、候选确认、绑定刷新、缓存、队列、竞态、旧缓存迁移、失败保留旧值及限流行为。运行 `npm run build` 完成打包与类型检查；`npm run lint:check` 检查格式和规则。

安装 `.scaffold/build/ccf-rank.xpi` 后，在 Zotero 中完成以下人工验收：

- 四列可选；数字按数值顺序排列，0 与空白区分；查询、歧义和错误状态可见。
- 选取带 DOI、无 DOI 但标题和作者 / 年份齐全、无法匹配、附件 / 笔记等条目，确认只对常规条目显示结果。
- 多选更新显示进度；关闭自动更新时无后台查询，开启后有效缓存不重复查询。
- 断网刷新保留旧数字和成功更新时间；恢复网络后手动刷新成功。
- 手动设为 0，批量刷新不覆盖；清除记录后恢复自动来源。
- 检索无 DOI 的《Open World Image Aesthetic Assessment》，确认标题和年份一致、作者信息缺失时仍能匹配；当前 OpenAlex ID 为 `W7220942938`。
- 对有歧义的论文打开「确认 OpenAlex 论文…」，核对差异后确认；来源保持 OpenAlex，重启和后续刷新仍使用绑定记录。
- 候选窗口打开期间修改文献标题或年份，旧确认按钮应拒绝绑定；关闭 Zotero 父窗口或卸载插件会关闭候选窗口。
- 重启 Zotero 后缓存仍在；修改 DOI / 标题 / 年份 / 第一作者不显示旧记录。
- 个人库和群组库的同名条目独立；删除 / 回收站处理正确。
- 打开第二个 Zotero 窗口、关闭窗口、禁用再启用插件，菜单和列无重复，卸载后不继续更新。

自动化测试使用数据源样例与 Zotero 接口模拟，不替代真实 Zotero 7–10 的 UI、排序和重启验收。
